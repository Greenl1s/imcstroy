# Статистика выдач в прототипе

Архив содержит только изменения относительно предыдущего обновления `imcstroy-equipment-trash-prototype-20261006.zip`. Предыдущее обновление и миграции 043, 044 должны быть установлены.

## Изменения

- При выборе проекта перед выдачей оставлен только выпадающий список. Поле поиска убрано.
- В левой панели прототипа добавлена **Статистика**; на телефоне доступна через **Ещё → Статистика выдач**.
- Над таблицей три кнопки: **Все**, **В работе**, **Возвращённые**. Числа обозначают количество отдельных выдач, а не уникальных приборов.
- Одна строка показывает прибор, сотрудника, проект, время выдачи и возврата. Время отображается по Москве.
- Повторная выдача создаёт новую запись. Дополнительная выдача количества по одной карточке также создаёт отдельную строку. При частичном возврате видно, сколько осталось; такая выдача остаётся в фильтре «В работе» до полного возврата. Частичные возвраты закрывают самые ранние выдачи этого сотрудника по данному прибору.
- Передача другому сотруднику меняет текущего держателя, но не считается возвратом на склад; первоначальный получатель сохраняется.
- Выдачи и возвраты через основной учёт или прототип фиксируются общей базой в той же транзакции, что изменение наличия. Интерфейс статистики добавлен только в прототип.
- Для большого количества записей есть кнопка «Показать ещё». Статистика обновляется при открытии, переключении фильтра и кнопкой «Обновить».

## Старые записи

Уже находящиеся на руках приборы появятся в текущих выдачах. Для одиночных приборов точное время берётся из сохранённой истории, если событие выдачи найдено. Если достоверного времени нет, показывается введённая дата и «Время не сохранено».

Из старой истории восстанавливаются завершённые выдачи одиночных приборов с однозначной парой «выдача — возврат». Для старых многоштучных приборов нельзя надёжно восстановить отдельные партии из объединённого остатка: их прежние завершённые выдачи не добавляются автоматически. Все новые выдачи и возвраты учитываются с момента миграции.

## Установка

Загрузите изменённые файлы в GitHub с сохранением путей. На сервере выполните из папки проекта:

```sh
git pull --ff-only
```

Перед миграцией сделайте свежую резервную копию базы. Далее каждую команду выполняйте отдельно; при ошибке остановитесь:

```sh
docker compose exec -T db sh -c 'psql -v ON_ERROR_STOP=1 -1 -U "$POSTGRES_USER" -d "$POSTGRES_DB"' < db/045_equipment_loan_statistics.sql
docker compose build api
docker compose up -d --no-deps api
docker compose logs --tail=40 api
```

Применение миграции ненадолго блокирует операции выдачи/возврата, чтобы перенести начальные остатки без потери событий. Перезапуск ИСУ, Caddy и AI-сервиса для этого обновления не требуется. Статические файлы прототипа уже подключены в предыдущем обновлении.

Откройте `https://files.imcstroy.ru/instruments-prototype/` и обновите страницу с очисткой кэша (`Ctrl+F5`). Перейдите в «Статистика».

## Проверки

Локально проверены отображение времени по Москве, частичные возвраты, безопасный вывод названий, фильтры и постраничная загрузка API. В Chrome с имитацией API проверены список проектов без поиска, отмена через Escape, выдача, общие остатки двух интерфейсов, переход в статистику и переключение фильтров.

Настоящие PostgreSQL-триггеры локально не запускались: в этой среде нет PostgreSQL/Docker. После миграции предусмотрена проверка в транзакции с откатом тестовых записей:

```sh
docker compose exec -T db sh -c 'psql -v ON_ERROR_STOP=1 -U "$POSTGRES_USER" -d "$POSTGRES_DB"' < tests/equipment-loans.sql
```

Ожидается сообщение `PASS` и в конце `ROLLBACK`. Проверяются одиночная и повторная выдача, проект, передача, дополнительные количества, частичный и полный возврат. При ошибке соединение закроется и тестовые изменения будут откачены PostgreSQL.

Локальная проверка интерфейсных данных и маршрута API: `node tests/loan-statistics.test.mjs`.
