# Учёт табеля

Самостоятельное приложение для заполнения месячных табелей. В репозитории ИСУ находится только исходный код отдельного проекта: базы данных, пользователи и запуск у него собственные.

**На сервере рядом с ИСУ:** используйте [пошаговую инструкцию](ЗАПУСК-НА-СЕРВЕРЕ.md). Она описывает отдельный Docker-проект, первый вход через SSH-туннель, подключение действующего Caddy и резервное копирование. Не переносите Compose-сервис табеля в основной файл ИСУ.

## Быстрый запуск на компьютере

Установите Node.js 24 LTS с официального сайта https://nodejs.org/. Затем откройте терминал в этой папке:

```sh
npm start
```

Откройте http://127.0.0.1:3180. При первом входе создайте своего администратора. Установка npm-зависимостей не требуется. Остановка — Ctrl+C. Данные сохраняются в `data/timesheets.sqlite` между запусками. Файлы нельзя открывать двойным щелчком как обычный HTML: приложению нужен сервер Node.js.

GitHub хранит исходники. GitHub Pages не запускает Node.js и SQLite, поэтому для работы с общими данными приложение следует запускать на компьютере или сервере. Инструкция для сервера подготовлена отдельно; сам работающий сервер из этой переписки не изменяется.

## Работа с приложением

1. В «Базе данных» добавьте сотрудников: ФИО, должность, необязательные дату рождения и примечание. Новая должность появится в матрице работ автоматически.
2. Добавьте обычные работы и работы в командировке. В соответствующей матрице поставьте «+» на пересечении должности и разрешённой работы. Пустая ячейка означает, что работа недоступна этой должности.
3. Добавьте подписантов: ФИО и должность в компании.
4. В «Делах» создайте табель, указав название и месяц с годом. Количество дней рассчитывается автоматически. В новом табеле нет заранее заполненных сотрудников.
5. Добавьте строку, выберите сотрудника и нажимайте ячейки нужных дней. В списке будут работы, разрешённые текущей должности сотрудника. На день выбирается одна работа: обычная либо командировка. В другой колонке появляется прочерк. Выбор другой категории заменяет прежнюю запись.
6. Над таблицей выберите подписанта. Для удобства можно смотреть неделю или весь месяц; экспорт Excel всегда содержит весь месяц. Длинные названия переносятся по строкам.
7. Нажмите «Завершить». Завершённый табель доступен для просмотра и выгрузки. Вернуть его в работу может только администратор. Пустые дни допустимы, например для выходных: перед завершением показывается предупреждение.

В Excel выгружается настоящий файл `.xlsx`: двухуровневая шапка, все дни, сотрудники и работы, подписант и строка для подписи вида «Иванов И.И. ________________». На листе закреплены шапка и колонка сотрудников.

## Права и сохранность

Администратор создаёт аккаунты в разделе «Пользователи». Администратор и сотрудник могут вести справочники и заполнять действующие табели. Управление аккаунтами и возврат завершённого табеля доступны только администратору. Ограничения проверяются сервером.

Пароли хешируются с scrypt и индивидуальной солью. Используются серверные сессии, CSRF-токены и проверка источника запросов. При параллельном изменении табеля сервер отклоняет устаревшую версию, чтобы не затереть чужое сохранение. Табели хранят снимки названий заполненных работ: последующее переименование справочника не переписывает старые записи. Удаление записей справочников архивирует их и сохраняет историю табелей.

По умолчанию сервер доступен только на этом компьютере. Не публикуйте папку `data`, резервные копии, `.env` и реальные персональные данные в GitHub. Для работы через интернет требуется HTTPS за обратным прокси, корректный `APP_ORIGIN` и отдельная настройка доступа. Предоставленная конфигурация не открывает порт в интернет.

## Docker (необязательно)

```sh
docker compose up -d --build
docker compose logs timesheets
```

Откройте http://127.0.0.1:3180. Для первой настройки Docker-версия выводит случайный код в журнал; введите его в форме создания администратора. Можно заранее задать `SETUP_TOKEN` в собственном `.env` по примеру `.env.example`. После создания администратора форма первичной настройки больше недоступна.

Контейнер запускается без root и дополнительных capabilities; данные — в отдельном Docker volume. Имя Compose-проекта — `uchet-tabelya`. Для остановки используйте `docker compose stop timesheets`. Этот Compose не запускает и не изменяет ИСУ. Для связи с существующим Caddy есть дополнение `compose.proxy.yml`; порядок его подключения описан в инструкции сервера.

## Резервная копия

Для копии без остановки выполните `node server/backup.mjs`: скрипт использует SQLite Backup API, сохраняет новый файл в `data/backups/` и проверяет целостность. В Docker он запускается через `docker compose exec -T timesheets node server/backup.mjs`; команды копирования результата на хост приведены в инструкции сервера. Скрипт не перезаписывает существующие файлы. Копии нужно регулярно переносить с сервера на отдельный защищённый носитель.

Для простого локального резервирования также можно остановить приложение и скопировать всю папку `data` в безопасное место вне GitHub. При восстановлении сначала остановите приложение. Не копируйте только основной файл SQLite во время работы: актуальные изменения могут находиться в WAL-файле.

## Проверки и устройство

```sh
npm test
```

Проверяются календарь, формат подписи, XLSX, создание справочников и табелей, матрицы разрешений, права двух ролей, завершение и возврат, конфликт сохранений, CSRF и сохранение базы после перезапуска. Тесты используют временную базу и не заполняют рабочую.

- `public/` — интерфейс HTML/CSS/JavaScript без внешних CDN.
- `server/server.mjs` — HTTP API, пользователи, SQLite и проверки прав.
- `server/xlsx.mjs` — формирование Excel OOXML.
- `tests/` — автоматические проверки.
- `compose.yml`, `Dockerfile` — отдельный запуск в Docker.

Переменные окружения приложения: `HOST` (по умолчанию `127.0.0.1`), `PORT` (`3180`), `DATABASE_PATH` (путь к SQLite), `APP_ORIGIN` (полный адрес сайта), `SETUP_TOKEN` (секрет первоначальной настройки). Переменные Compose: `TIMESHEET_PORT` (порт хоста, по умолчанию 3180), `TIMESHEET_PROXY_NETWORK` (имя существующей сети Caddy, только для `compose.proxy.yml`). Требуется Node.js 24 или новее с поддержкой `node:sqlite`.
