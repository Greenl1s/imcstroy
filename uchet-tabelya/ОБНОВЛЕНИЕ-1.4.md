# Табельный учёт 1.4.0

## Изменения

- Название «Табельный учёт» в заголовке вкладки, навигации и входе.
- На левой части входа только крупное название системы. Рекламный текст убран.
- Раздел «Дела» называется «Табели». На главной только Табели и База данных.
- Один сотрудник (одна запись справочника) может иметь работу за конкретную дату
  только в одном табеле. Обычная работа и командировка учитываются совместно.
  Проверяются табели в работе и завершённые. Другая дата/месяц/год не конфликтуют.
- Занятая дата обозначена «Занят»; при выборе показано название табеля.
  Сервер повторно проверяет занятость внутри транзакции, включая параллельные запросы.
- Очистка дня, удаление строки, замена сотрудника с очисткой и удаление табеля
  освобождают занятые даты. Завершённый табель сначала возвращает в работу администратор.
- В карточке табеля у администратора кнопка «Удалить навсегда», включая завершённые.
  Удаляются табель и его история; справочники и другие табели сохраняются.
  Нужны подтверждение и актуальная версия табеля; у сотрудника API возвращает 403.

Существующие заполненные табели не переписываются автоматически. Если в них уже
есть совпадения, нужно выбрать правильный табель и очистить лишние записи.
Завершить табель с таким конфликтом система не позволит. Записи одного человека,
ошибочно заведённые в справочнике как разные сотрудники, считаются разными:
проверка использует ID сотрудника, а не совпадение текста ФИО.

«Удалить навсегда» означает отсутствие восстановления в приложении. Ранее
сделанные резервные копии и скачанные Excel-файлы эта кнопка не удаляет.

## Обновление действующей установки

На Windows, в PowerShell (архив создан в рабочей папке Codex):

```powershell
scp "C:\Users\user\Documents\Codex\2026-09-19\new-chat\outputs\uchet-tabelya-changes-1.4.zip" admin@213.171.26.248:/home/admin/
```

На сервере выполните блок целиком. Команды соединены &&: при ошибке обновление
остановится. Копия базы создаётся в действующем Docker volume; копия изменяемых
исходных файлов — в /home/admin/backups/uchet-tabelya/.

```bash
cd /home/admin/apps/uchet-tabelya &&
mkdir -p /home/admin/backups/uchet-tabelya &&
tar -czf "/home/admin/backups/uchet-tabelya/source-before-1.4-$(date +%Y%m%d-%H%M%S).tar.gz" public/app.js public/index.html public/style.css server/server.mjs package.json tests &&
docker compose -p uchet-tabelya -f compose.yml -f compose.proxy.yml exec -T timesheets node server/backup.mjs &&
python3 -m zipfile -e /home/admin/uchet-tabelya-changes-1.4.zip /home/admin/apps/uchet-tabelya &&
docker compose -p uchet-tabelya -f compose.yml -f compose.proxy.yml up -d --build --no-deps timesheets &&
docker compose -p uchet-tabelya -f compose.yml -f compose.proxy.yml ps timesheets &&
curl -fsS http://127.0.0.1:3180/tabel/api/health
```

Откройте https://files.imcstroy.ru/tabel/ и нажмите Ctrl+F5.
База, аккаунты, .env, Compose и Caddy не заменяются. Сервис табеля кратковременно
перезапустится. ИСУ и учёт оборудования не перезапускаются.

Проверка: создайте два тестовых табеля одного месяца, добавьте одного и того же
сотрудника и заполните одинаковый день. Во втором табеле выбор должен быть
заблокирован. Очистите день в первом и заполните во втором. Под сотрудником кнопки
удаления табеля быть не должно; под администратором проверьте её на тестовом табеле.

Автоматические проверки: 32 теста — API, параллельные запросы, роли, формы,
экспорт, HTTPS-прокси /tabel/, резервное копирование и сохранность после перезапуска.
Визуальная проверка установленной версии выполняется после обновления сервера.
