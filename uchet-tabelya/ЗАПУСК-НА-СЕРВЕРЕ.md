# Запуск «Учёта табеля» рядом с ИСУ и учётом оборудования

Инструкция для Linux-сервера с Docker Compose. В изученной копии вашего репозитория сайты обслуживает контейнер `caddy:2-alpine`; ниже описан этот вариант. Фактические имена контейнера, сети и путь к Caddyfile сначала определяем командами. Если на работающем сервере используется другой прокси, выполните только этапы 1–4 и пришлите его конфигурацию без секретов для адаптации этапа 5.

Результат: отдельный контейнер табеля, собственные аккаунты и база SQLite в Docker volume. ИСУ и учёт оборудования продолжают использовать свои сервисы. Порты 80/443 остаются у действующего Caddy. Приложение табеля слушает внутренний порт 3180; на сервере он опубликован только на `127.0.0.1`. Для публичного адреса предлагается **`tabel.imcstroy.ru`** — это пример, DNS-запись ещё не создана. Приложение рассчитано на отдельный поддомен, не на путь `/tabel/` внутри ИСУ.

## 1. На компьютере Windows: отправить архив

Скачайте новый архив `uchet-tabelya-server.zip`. Подставьте в команду свои имя пользователя и адрес **того сервера, где работает ИСУ**, используя привычные вам параметры SSH. Адрес домашнего сервера здесь не требуется.

В PowerShell (путь ниже соответствует архиву, подготовленному в этой переписке):

```powershell
scp "C:\Users\user\Documents\Codex\2026-09-19\new-chat\outputs\uchet-tabelya-server.zip" USER@SERVER:~/
ssh USER@SERVER
```

`USER@SERVER` — заполнитель, замените его. Если при обычном входе используете `-i` и `-p`, укажите их и здесь; у `scp` номер SSH-порта задаётся большой `-P`.

Загрузка из архива позволяет установить табель сейчас: отправка исходников на GitHub в предыдущем шаге не состоялась. Не запускайте `git pull` всего рабочего репозитория ради установки табеля — это могло бы принести другие изменения ИСУ. На GitHub исходники предназначены для отдельной папки `uchet-tabelya` в общем репозитории; рабочую копию сервера ниже размещаем в `~/apps/uchet-tabelya`.

## 2. На Linux-сервере: проверить окружение и распаковать

```bash
sudo docker compose version
sudo docker ps --format 'table {{.Names}}\t{{.Ports}}'
sudo ss -lntp 'sport = :3180'
```

Если 3180 уже занят, выберите другой свободный порт, например 3182. В примерах дальше используется 3180. Не меняйте порты работающих приложений.

Для **первой установки**:

```bash
mkdir -p ~/apps
unzip ~/uchet-tabelya-server.zip -d ~/apps
cd ~/apps/uchet-tabelya
umask 077
cp .env.example .env
chmod 600 .env
nano .env
```

Если `unzip` не установлен: `sudo apt install unzip`. Если папка уже существует и в ней работал табель, сначала сохраните `.env` и резервную копию базы, затем используйте раздел обновления. Не создавайте заново `.env` поверх существующего.

На первом этапе оставьте:

```dotenv
APP_ORIGIN=http://127.0.0.1:3180
TIMESHEET_PORT=3180
SETUP_TOKEN=
```

При смене локального порта измените и `TIMESHEET_PORT`, и порт в HTTP-адресе `APP_ORIGIN`. Внутри контейнера порт остаётся 3180.

## 3. На Linux-сервере: запустить только табель

Все команды этого этапа вводятся из **`~/apps/uchet-tabelya`**:

```bash
sudo docker compose -p uchet-tabelya -f compose.yml config --quiet
sudo docker compose -p uchet-tabelya -f compose.yml up -d --build
sudo docker compose -p uchet-tabelya -f compose.yml ps
curl -fsS http://127.0.0.1:3180/api/health
sudo docker compose -p uchet-tabelya -f compose.yml logs --tail=30 timesheets
```

Ожидается `{"ok":true}` и через некоторое время статус `healthy`. В журнале первого запуска будет код первоначальной настройки. Не отправляйте этот код в чат. При пустом `SETUP_TOKEN` код может измениться, если контейнер перезапущен до создания администратора; возьмите код из свежего журнала.

Проект Compose называется `uchet-tabelya`, сервис — `timesheets`, том базы при таком запуске — `uchet-tabelya_timesheet-data`. Явное имя проекта сохраняйте во всех командах. Если раньше запускали приложение с другим `-p`, его база находится в другом томе: сначала определите прежнее имя проекта, не удаляйте тома.

Не открывайте порт 3180 в firewall и не ставьте второй Caddy/Nginx на порты 80/443. Node.js и отдельную СУБД на хост устанавливать не требуется: всё нужное находится в контейнере. Для приложения настроены автозапуск после перезагрузки Docker, лимиты 512 МБ RAM / 1 CPU, ротация журналов и проверка состояния. Статус `unhealthy` сообщает о проблеме, но сам по себе не перезапускает контейнер; `restart: unless-stopped` перезапускает завершившийся процесс.

## 4. На Windows: безопасно создать первого администратора

До публикации DNS-адреса откройте **второе окно PowerShell** и оставьте его работающим:

```powershell
ssh -N -L 3180:127.0.0.1:3180 USER@SERVER
```

При необходимости добавьте обычные параметры своего SSH-ключа и SSH-порта. Если локальный порт Windows занят, используйте слева другое число, но тогда временно согласуйте `APP_ORIGIN` с адресом, открываемым в браузере. Проще использовать свободный одинаковый порт с обеих сторон.

Откройте на Windows **http://127.0.0.1:3180**. Создайте администратора, введя код из журнала контейнера. После входа добавьте тестового сотрудника, одну работу, разрешение для его должности, подписанта и небольшой табель; проверьте экспорт Excel. Эти действия заполняют вашу новую базу табеля, не базы ИСУ.

Туннель передаёт соединение через SSH. Публичный сайт на этом этапе ещё не настроен. Переходите к этапу 5 после успешного входа.

## 5. На Linux-сервере: подключить существующий Caddy

### Найти контейнер, сеть и действующий файл

```bash
sudo docker ps --format 'table {{.Names}}\t{{.Image}}'
```

Найдите строку Caddy. Подставьте **реальное имя из списка**, например `imcstroy-caddy-1`:

```bash
CADDY_CONTAINER='imcstroy-caddy-1'
sudo docker inspect "$CADDY_CONTAINER" --format '{{range $name, $_ := .NetworkSettings.Networks}}{{println $name}}{{end}}'
sudo docker inspect "$CADDY_CONTAINER" --format '{{range .Mounts}}{{if eq .Destination "/etc/caddy/Caddyfile"}}{{println .Source}}{{end}}{{end}}'
```

Запишите имя обычной Docker bridge-сети Caddy, например `imcstroy_default`. Если сетей несколько, используйте ту, через которую Caddy общается с сервисами ИСУ. Не создавайте сеть с выдуманным именем вместо существующей. Команды ниже предполагают, что `/etc/caddy/Caddyfile` смонтирован отдельным файлом с хоста, как в репозитории. Если путь не показан или используется `host`-сеть, остановитесь на этом этапе: конфигурацию нужно адаптировать.

### Подготовить DNS и окружение табеля

В управлении DNS вашего домена создайте запись **A**: `tabel` → публичный IPv4 текущего сервера ИСУ. Если у этого имени есть AAAA, она должна указывать на доступный IPv6 того же сервера; не оставляйте устаревший адрес. Для первоначальной настройки сертификата удобно использовать обычную DNS-запись без стороннего HTTP-проксирования. Caddy использует уже доступные порты 80/443.

На сервере:

```bash
cd ~/apps/uchet-tabelya
nano .env
```

Укажите реальный домен и **найденное** имя сети:

```dotenv
APP_ORIGIN=https://tabel.imcstroy.ru
TIMESHEET_PORT=3180
TIMESHEET_PROXY_NETWORK=imcstroy_default
SETUP_TOKEN=
```

После создания администратора повторная первоначальная настройка закрыта. `APP_ORIGIN` должен точно совпадать с адресом браузера: протокол, домен и нестандартный порт, если он есть; без завершающего `/`. При HTTPS приложение выставляет сессионной cookie флаг `Secure`.

```bash
sudo docker compose -p uchet-tabelya -f compose.yml -f compose.proxy.yml config --quiet
sudo docker compose -p uchet-tabelya -f compose.yml -f compose.proxy.yml up -d --build
sudo docker compose -p uchet-tabelya -f compose.yml -f compose.proxy.yml ps
sudo docker exec "$CADDY_CONTAINER" wget -qO- http://imcstroy-timesheets-web:3180/api/health
```

Последняя команда в образе `caddy:2-alpine` должна вернуть `{"ok":true}`. Прокси обращается к сервису по Docker DNS-имени **`imcstroy-timesheets-web:3180`**, а не к `127.0.0.1:3180`: внутри контейнера Caddy localhost относится к самому Caddy. Дополнительный Compose-файл подключает только табель к уже существующей сети; аккаунты и SQLite остаются отдельными. Остальные сервисы этой сети технически могут обращаться к порту табеля, но API с данными требует авторизации.

### Добавить отдельный блок в Caddyfile и проверить до применения

Не заменяйте весь Caddyfile готовым примером — в нём остаются блоки ИСУ, оборудования и OnlyOffice.

В том же SSH-сеансе:

```bash
CADDYFILE_PATH=$(sudo docker inspect "$CADDY_CONTAINER" --format '{{range .Mounts}}{{if eq .Destination "/etc/caddy/Caddyfile"}}{{.Source}}{{end}}{{end}}')
sudo test -f "$CADDYFILE_PATH"
CADDY_BACKUP="${CADDYFILE_PATH}.before-timesheets-$(date -u +%Y%m%dT%H%M%SZ)"
sudo cp -a "$CADDYFILE_PATH" "$CADDY_BACKUP"
sudo cp -a "$CADDYFILE_PATH" "$HOME/Caddyfile.with-timesheets"
sudo nano "$HOME/Caddyfile.with-timesheets"
```

Если `test` завершился с ошибкой, следующие команды не выполняйте: сначала найдите правильный файл. В конец **копии** допишите блок из `deploy/Caddyfile.example`, заменив адрес при необходимости:

```caddyfile
tabel.imcstroy.ru {
    encode gzip
    reverse_proxy imcstroy-timesheets-web:3180
    header {
        X-Content-Type-Options nosniff
        Referrer-Policy same-origin
        -Server
    }
}
```

Проверьте копию, пока рабочий файл ещё не изменён:

```bash
sudo docker cp "$HOME/Caddyfile.with-timesheets" "$CADDY_CONTAINER:/tmp/Caddyfile.timesheets"
sudo docker exec "$CADDY_CONTAINER" caddy validate --config /tmp/Caddyfile.timesheets --adapter caddyfile
```

**Только после `Valid configuration`** примените её и перечитайте конфигурацию:

```bash
sudo cat "$HOME/Caddyfile.with-timesheets" | sudo tee "$CADDYFILE_PATH" >/dev/null
sudo docker exec "$CADDY_CONTAINER" caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile
sudo docker exec "$CADDY_CONTAINER" caddy reload --config /etc/caddy/Caddyfile --adapter caddyfile
```

Если повторная валидация сообщает ошибку, `reload` не выполняйте: используйте откат ниже. Запись через `tee` сохраняет сам смонтированный файл, чтобы контейнер видел обновление. Не запускайте `docker compose down` ИСУ для изменения Caddyfile.

```bash
curl -fsS https://tabel.imcstroy.ru/api/health
sudo docker logs --tail=50 "$CADDY_CONTAINER"
```

Теперь в браузере Windows откройте **https://tabel.imcstroy.ru**, войдите созданным администратором. Старый HTTP-сеанс через туннель больше не используйте: после смены `APP_ORIGIN` вход должен происходить по HTTPS. Caddy получает сертификат после корректного DNS и доступности сервера.

## 6. Проверить после запуска

- Открываются ИСУ, учёт оборудования и редактор документов по прежним адресам.
- Табель открывается по новому HTTPS-адресу; без входа справочники не доступны.
- Созданный табель сохраняется после обновления страницы; Excel выгружается и открывается.
- Сотрудник завершает табель, но не может вернуть его в работу; администратор может.
- `docker compose ... ps` показывает `healthy`.

## 7. Резервная копия без остановки

Используется SQLite Backup API, а не копирование одного live-файла базы. На сервере из `~/apps/uchet-tabelya`:

```bash
cd ~/apps/uchet-tabelya
umask 077
mkdir -p "$HOME/backups/uchet-tabelya"
BACKUP_NAME="timesheets-$(date -u +%Y%m%dT%H%M%SZ).sqlite"
sudo docker compose -p uchet-tabelya -f compose.yml exec -T timesheets node server/backup.mjs "/app/data/backups/$BACKUP_NAME"
TAB_CONTAINER=$(sudo docker compose -p uchet-tabelya -f compose.yml ps -q timesheets)
sudo docker cp "$TAB_CONTAINER:/app/data/backups/$BACKUP_NAME" "$HOME/backups/uchet-tabelya/$BACKUP_NAME"
sudo chown "$(id -u):$(id -g)" "$HOME/backups/uchet-tabelya/$BACKUP_NAME"
chmod 600 "$HOME/backups/uchet-tabelya/$BACKUP_NAME"
```

Команда `exec` здесь намеренно использует только основной файл: ей нужен ID существующего контейнера, а не его пересоздание. Продолжайте копирование только после успешного завершения `backup.mjs`. Скрипт не перезаписывает существующий файл и проверяет целостность копии. Дубли остаются в томе (`/app/data/backups`) и в указанной папке хоста; следите за свободным местом, автоматическое удаление копий не настроено. Регулярно переносите копии ещё и на другой носитель/сервер с ограниченным доступом. Они содержат персональные данные и хеши паролей; в GitHub их не загружать.

Восстановление выполняется при остановленном **табеле**, с сохранением текущего тома и заменой базы на выбранную проверенную копию. Нельзя подменять SQLite во время работы контейнера. Если понадобится восстановление, сначала зафиксируйте имя проекта, текущий том и файл копии — команды следует составить под эти конкретные пути.

## 8. Обновление и остановка

Сначала сделайте резервную копию по этапу 7. Новый архив распаковывайте поверх **той же папки**; он не содержит `.env` и рабочей базы. Не меняйте имя Compose-проекта и тома. В новой версии сначала проверьте инструкцию на необходимость миграций.

Для версии с публичным доменом:

```bash
cd ~/apps/uchet-tabelya
sudo docker compose -p uchet-tabelya -f compose.yml -f compose.proxy.yml config --quiet
sudo docker compose -p uchet-tabelya -f compose.yml -f compose.proxy.yml up -d --build
sudo docker compose -p uchet-tabelya -f compose.yml -f compose.proxy.yml ps
```

Для локальной установки без этапа 5 опускайте `-f compose.proxy.yml`. После подключения прокси при каждом `up` сохраняйте **оба** `-f`, иначе новый контейнер потеряет связь с Caddy. Команды запускайте из папки табеля. Для остановки только табеля:

```bash
sudo docker compose -p uchet-tabelya -f compose.yml stop timesheets
```

Не используйте `down -v`, `docker volume prune` или `docker system prune --volumes`: они могут удалить данные. Если основной проект ИСУ когда-либо потребуется полностью удалить командой `down`, сначала остановите и удалите контейнер табеля командой `docker compose -p uchet-tabelya -f compose.yml -f compose.proxy.yml down` **без `-v`**: он использует внешнюю сеть Caddy и иначе не даст удалить эту сеть. После восстановления сети ИСУ снова поднимите табель с обоими Compose-файлами. Обычное обновление/пересоздание Caddy при сохранении сети этого не требует.

## 9. Если новый адрес не работает

- `502`: проверьте `healthy`, правильное имя сети и запрос `wget` из контейнера Caddy к `imcstroy-timesheets-web:3180`.
- Ошибка сертификата: проверьте A/AAAA и журнал Caddy. Не отключайте проверку сертификатов в браузере.
- Ошибка входа/«Запрос с другого сайта запрещён»: проверьте точное значение `APP_ORIGIN`, затем пересоздайте только табель командой `up -d` с обоими файлами и войдите заново.
- `port is already allocated`: выберите свободный `TIMESHEET_PORT`. Порт Docker-сервиса и Caddy upstream остаётся 3180.
- Ошибка создания базы/volume: посмотрите журнал `timesheets`; не удаляйте том для «исправления».

Для отката только настройки Caddy в том же сеансе, где заданы переменные:

```bash
sudo test -f "$CADDY_BACKUP"
sudo cat "$CADDY_BACKUP" | sudo tee "$CADDYFILE_PATH" >/dev/null
sudo docker exec "$CADDY_CONTAINER" caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile
sudo docker exec "$CADDY_CONTAINER" caddy reload --config /etc/caddy/Caddyfile --adapter caddyfile
```

Снова выполняйте `reload` только после успешной валидации. При новом SSH-сеансе сначала восстановите значения `CADDY_CONTAINER`, `CADDYFILE_PATH` и точный путь `CADDY_BACKUP`. Откат Caddy не удаляет табели и SQLite.
