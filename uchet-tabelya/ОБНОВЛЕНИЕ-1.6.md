# Табельный учёт 1.6.0

## Роли и права 1.6

В разделе «Пользователи» появилась кнопка «Добавить роль» и список именованных ролей.
У роли есть название и подробный список разрешений с кнопками «Выбрать всё» и «Снять всё».
Создайте роль, затем откройте «Доступ» у пользователя и выберите её в списке
«Назначенная роль». Ту же роль можно выбрать при создании нового аккаунта.
Одна роль может быть назначена нескольким пользователям.

Действия редактора соответствуют существующим операциям:

- Табели: просмотр, создание, редактирование реквизитов/строк/дней, Excel,
  завершение, возврат в работу, удаление.
- Сотрудники: просмотр, добавление, изменение, исключение из справочника.
- Должности: просмотр и добавление (изменение и удаление должностей пока не реализованы).
- Виды работ: просмотр, добавление, изменение, исключение; обе категории —
  обычные работы и командировки.
- Матрица: разрешение и запрет работ для должностей.
- Подписанты: просмотр, добавление, изменение, исключение.
- Планирование: просмотр, создание, редактирование, подтверждение.
- Верификация и Контроль: просмотр, редактирование, подтверждение отдельно.

Разрешение действия автоматически включает необходимый просмотр. Добавление и
изменение сотрудников также разрешает просмотр должностей для их выбора.
Для работы с матрицей включается просмотр должностей и работ.
Подтверждение без редактирования возможно: пользователь проверяет и передаёт
сохранённую таблицу, но не меняет строки. У согласованных таблиц редактирование
по-прежнему закрыто.

Управление аккаунтами и ролями доступно только системному администратору.
Это фиксированное ограничение, оно не выдаётся галочкой пользовательской роли.
Полномочия системного администратора нельзя ограничить или расширить редактором.
Удалить назначенную действующему пользователю роль нельзя: сначала переназначьте роль.
При изменении роли новые серверные ограничения действуют немедленно; обновите страницу,
чтобы интерфейс также показал новый набор кнопок.

Предыдущий индивидуальный доступ по разделам сохранён для совместимости.
Если выбрана именованная роль, действуют ТОЛЬКО её права. После снятия назначения
можно снова настроить индивидуальные разделы. Старые аккаунты не получают новых
разрешений на удаление или возврат табелей автоматически. Именованная роль может
получить эти права, если администратор явно отметит соответствующие пункты.

Исправлены размеры текстовых кнопок в действиях пользователей и ролей:
они больше не используют фиксированную ширину маленькой кнопки-иконки.
На узком экране кнопки переносятся; широкая таблица прокручивается горизонтально.

Проверено 40 автотестами. Визуальная проверка рабочей страницы после установки
ещё требуется; обновление на сервер в этой сессии не устанавливалось.

## Возможности предыдущего выпуска (сохранены)

На главной администратора пять разделов: Табели, База данных, Планирование,
Верификация, Контроль. В списке пользователей доступны настройка доступа и удаление.
Для сотрудника можно отметить любую комбинацию из пяти разделов, в том числе
один, все или ни одного. Администратор всегда имеет полный доступ.

Существующие сотрудники сохраняют доступ к Табелям и Базе данных. Доступ к новым
этапам им назначает администратор. После изменения доступа обновите страницу
сотрудника: сервер применяет новые права сразу, даже к старой открытой странице.
Если База данных недоступна, сотрудник с доступом к Табелям всё равно может
выбирать сотрудников, разрешённые работы и подписанта; менять справочники нельзя.
Минимальный справочник для табелей не отдаёт даты рождения и примечания.

Удалённый пользователь исчезает из списка и больше не может войти; его сессии
аннулируются. Запись помечается удалённой, чтобы сохранить авторство действий.
Прежний логин остаётся зарезервированным. Удалить собственный аккаунт нельзя.

## Общая таблица и этапы

1. Планирование: создайте таблицу, выберите месяц, добавьте строки.
2. Строки: Сотрудник, Работа / задача, Дата, Примечание. Пока это текстовые поля,
   а не распределение по сотрудникам справочника. Точный формат можно уточнить позже.
3. «Сохранить» сохраняет текущий вариант. Перед выходом из редактора сохраните правки.
4. «Подтвердить» сохраняет правки и передаёт таблицу в Верификацию.
5. Пользователь с доступом к Верификации открывает, редактирует и подтверждает её.
6. Таблица переходит в Контроль. Контролёр также может редактировать и подтвердить.
7. После контроля — состояние «Согласовано», просмотр без редактирования.

Пользователь видит таблицы только на доступных ему этапах. При передаче вперёд
предыдущий этап больше не может менять таблицу. Администратор или сотрудник с
несколькими разрешениями может работать на всех назначенных ему этапах.
Состояния и история сохраняются после перезапуска; параллельные правки проверяются
по версии таблицы. Пропустить этап передачей произвольного статуса через API нельзя.

Распределение согласованной таблицы по табелям пока НЕ реализовано, как согласовано.
Старые табели продолжают работать отдельно, проверка занятости сотрудника сохранена.

В PowerShell на Windows:

```powershell
scp "C:\Users\user\Documents\Codex\2026-09-19\new-chat\outputs\uchet-tabelya-changes-1.6.zip" admin@213.171.26.248:/home/admin/
```

На сервере:

```bash
cd /home/admin/apps/uchet-tabelya &&
mkdir -p /home/admin/backups/uchet-tabelya &&
tar -czf "/home/admin/backups/uchet-tabelya/source-before-1.6-$(date +%Y%m%d-%H%M%S).tar.gz" public server package.json tests &&
docker compose -p uchet-tabelya -f compose.yml -f compose.proxy.yml exec -T timesheets node server/backup.mjs &&
python3 -m zipfile -e /home/admin/uchet-tabelya-changes-1.6.zip /home/admin/apps/uchet-tabelya &&
docker compose -p uchet-tabelya -f compose.yml -f compose.proxy.yml up -d --build --no-deps timesheets &&
docker compose -p uchet-tabelya -f compose.yml -f compose.proxy.yml ps timesheets &&
curl -fsS http://127.0.0.1:3180/tabel/api/health
```

Обновите страницу Ctrl+F5. Табель кратковременно перезапустится.
Миграция базы выполняется при запуске: создаётся справочник ролей и связь пользователя с ролью; добавляются поля доступа, признак удалённого
пользователя и отдельная таблица согласования. Табели, аккаунты и документы не очищаются.
.env, Docker Compose, Caddy, ИСУ и учёт оборудования не меняются.

ОБЯЗАТЕЛЬНО добавьте server/workflow.mjs и НОВЫЙ server/permissions.mjs: прежняя команда обновления только
app.js для этого выпуска не подходит.

