# Табельный учёт 2.0.0 — месячная таблица и табели по полигонам

## Первый запуск после обновления

1. Откройте **Настройки → Зарплата и типы занятости**. Укажите базовую месячную
   сумму. Начальные типы: 1 — Командировка (синий), 2 — Офис (красный),
   3 — Общая (зелёный). Коды однозначные и уникальные, названия и цвета изменяемые.
2. В **База данных → Сотрудники** заполните подразделение и коэффициент каждого
   действующего сотрудника. Поле даты рождения заменено в интерфейсе коэффициентом;
   старые данные не стираются из базы при обновлении. Нулевой коэффициент допустим,
   но отсутствие значения не приравнивается к нулю. Коэффициент — не более 6 знаков
   после запятой. Зарплата — не более 2 знаков после запятой.
3. В **База данных → Полигоны** добавьте номера и названия. Номер 0 допустим,
   многозначные номера тоже: 2 (офис) + 12 (номер полигона) отображаются как 212.
4. В **База данных → Работы общих таблиц** создайте отдельные работы с шифрами.
   Отметьте «+» в матрице напротив разрешённых должностей. Это отдельный справочник,
   прежние виды работ обычных табелей в него автоматически не переносятся.
5. В **Настройки → Пользователи и роли** проверьте права ответственных. Добавлены
   права для полигонов, нового справочника работ, его матрицы и экспорта каждого этапа.
   Именованные роли не получают новые права автоматически; администратор имеет все.

## Планирование → Верификация → Контроль

В Планировании создайте общую таблицу с названием и месяцем. На месяц разрешена
одна таблица во всей системе, независимо от её стадии и создателя.
При создании автоматически подставляются все действующие сотрудники, их должности
и подразделения. Вместе с месяцем фиксируются коэффициенты, базовая сумма, коды
занятости и календарь. Их последующее изменение в справочниках не меняет созданный
месяц. Перед созданием проверьте настройки: пересоздание месяца не предусмотрено.

В Планировании и Верификации видны только №, подразделение, ФИО, должность и дни.
Сервер также не отдаёт поля зарплаты на этих стадиях, а не просто скрывает колонки.
В ячейке выберите тип занятости, полигон и разрешённую работу. На экране отображается
код места, например 212. Название и шифр работы видны при открытии ячейки.
Изменение сохраняется сразу. «Очистить день» означает отсутствие работы.

Кнопки передачи: **Передать на проверку**, затем **Передать на контроль**.
После передачи предыдущий этап больше не редактирует таблицу. Контроль добавляет:
коэффициент, зарплату ВСМ, дневную ставку, число заполненных дней и начисленную сумму.
Дни на контроле также редактируются согласно правам роли.

Расчёт: месячная зарплата = база × коэффициент; дневная ставка = месячная зарплата /
рабочие дни месяца; начислено = месячная зарплата × отработанные дни / рабочие дни.
Месячная зарплата округляется до копеек, дневная ставка для расчёта используется без
промежуточного округления; итог начисления округляется до копеек. В интерфейсе
денежные значения отображаются с двумя знаками после запятой. Пустой день не считается.

На контроле можно выбрать подписанта. Он сохраняется в сформированных табелях и
выгрузке Excel со строкой для подписи. Если подписант не выбран, в Excel остаётся
пустая строка для подписи; формирование этим не блокируется.

**Сформировать табель** создаёт все табели по использованным полигонам одной транзакцией.
При ошибке откатывается вся операция. Сотрудник попадает только в те полигоны,
где у него заполнены дни. В табеле — одна ячейка на день с шифром работы и цветом
занятости. Другие дни пустые. Сотрудники без работ не включаются в табели полигонов.
Полностью пустая общая таблица не формирует табели.

После формирования источник получает статус «Табели сформированы». Редактирование
дней, возврат в предыдущую стадию и повторная генерация запрещены, в том числе при
повторном нажатии или параллельных запросах. В разделе **Табели → По полигонам**
сначала видны полигоны, внутри — месяцы от новых к старым.

Ранее предоставленное право **Удалить табель** сохранено: пользователь с этим правом
может удалить сформированный отчёт с подтверждением. Исходная общая таблица и её
расчёт сохраняются, но удаление НЕ разрешает повторное формирование. Не удаляйте
нужные отчёты: восстановления через интерфейс нет. Редактировать или вернуть
сформированный табель в работу нельзя.

Если в прежнем ручном табеле уже отмечен тот же сотрудник за ту же дату, формирование
сообщит о конфликте вместо двойного учёта. Старые ручные табели доступны отдельно
в папке «Ранее созданные табели», со своим прежним представлением и экспортом.

## Календарь

Подключена пятидневка РФ на **2026 и 2027 годы**, включая праздники и переносы.
Нерабочие дни помечаются во всех новых месячных таблицах и выгрузках; записывать
работу в них нельзя ни через форму, ни через API. Перенесённая рабочая суббота,
например 20.02.2027, является рабочей.

Источники: https://www.cbr.ru/other/holidays/ и постановление №1466 от 24.09.2025:
https://static.government.ru/media/files/4jeB8hNKm69ggOa9yDiYOli6YoAyM21i.pdf.

Для другого года администратор открывает **Настройки → Производственный календарь**,
указывает дополнительные нерабочие и перенесённые рабочие даты, источник и подтверждает
год. Базовые субботы/воскресенья и федеральные праздники уже учитываются; прочие
переносы нужно перечислить по официальному календарю выбранного года. До подтверждения
неизвестного года создать его месяцы нельзя. Для известных лет те же настройки позволяют
учесть дополнительные нерабочие дни организации. Повторное сохранение заменяет список
дополнительных дат выбранного года. Созданные месяцы сохраняют прежний календарь.

## Старые пробные общие таблицы

Они не превращаются в новые месячные сетки автоматически. Чтобы использовать уже
занятый старой таблицей месяц, администратор открывает её и нажимает
**Перевести в месячную форму** с подтверждением. Это создаёт пустую месячную сетку
со всеми текущими сотрудниками и начинает согласование с Планирования. Прежнее
содержимое сохраняется внутри записи базы и в сделанной перед обновлением резервной
копии, но не переносится по дням автоматически. Новые месячные таблицы так преобразовать
или пересоздать нельзя. Если до обновления за один месяц было несколько старых
пробных таблиц, потребуется их отдельное согласованное объединение: обновление не
удаляет их автоматически и не выбирает одну за пользователя.

## Обновление через архив

В PowerShell на Windows:

```powershell
scp "C:\Users\user\Documents\Codex\2026-09-19\new-chat\outputs\uchet-tabelya-changes-2.0.zip" admin@213.171.26.248:/home/admin/
```

На сервере выполните блок целиком:

```bash
cd /home/admin/apps/uchet-tabelya &&
mkdir -p /home/admin/backups/uchet-tabelya &&
tar -czf "/home/admin/backups/uchet-tabelya/source-before-2.0-$(date +%Y%m%d-%H%M%S).tar.gz" public server package.json tests &&
docker compose -p uchet-tabelya -f compose.yml -f compose.proxy.yml exec -T timesheets node server/backup.mjs &&
python3 -m zipfile -e /home/admin/uchet-tabelya-changes-2.0.zip /home/admin/apps/uchet-tabelya &&
docker compose -p uchet-tabelya -f compose.yml -f compose.proxy.yml up -d --build --no-deps timesheets &&
docker compose -p uchet-tabelya -f compose.yml -f compose.proxy.yml ps timesheets &&
curl --retry 8 --retry-connrefused --retry-delay 1 -fsS http://127.0.0.1:3180/tabel/api/health
```

Ожидается `{"ok":true}`. Откройте https://files.imcstroy.ru/tabel/ и нажмите Ctrl+F5.
Миграция SQLite выполняется при запуске. Новые поля сотрудников, справочники,
настройки и месяцы сохраняются в прежнем Docker volume. .env, Compose и Caddy не
заменяются. ИСУ и учёт оборудования не перезапускаются.

Обновлять только app.js нельзя: в выпуске новые серверные модули. При откате
пользуйтесь резервной копией базы и исходников до обновления; возврат только старого
кода не отменяет миграцию схемы.

## Проверки

51 автоматический тест: прежние сценарии, права ролей, календарь и переносы,
деньги и округление, автоматические строки, уникальность месяца при параллельном
создании, запрет нерабочих дней, ограничения работ по должностям, недоступность
зарплаты до контроля, исторические значения, передача стадий, подписант, разделение
по полигонам 0 и 12, откат при ошибке второго табеля, двойное нажатие генерации,
запрет повторной генерации после удаления отчёта и сохранность после перезапуска.
Структура новых XLSX дополнительно проверена чтением сохранённых файлов: колонки,
значения зарплаты, подпись, шифры и цвета. Проверка внешнего вида в браузере и
настольном Excel ещё требуется на установленной версии; предпросмотр из среды
разработки недоступен.
