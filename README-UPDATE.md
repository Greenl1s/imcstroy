# Удаление проектов и очистка структуры

В архиве только изменённые файлы проекта (6 файлов и новая миграция 048).

## Что изменилось

- «Удалить проект» доступно администратору в карточке и форме редактирования проекта.
- Окно открывает конкретный проект в Planfix. Там нужно выбрать «Удалить проект» в деталях проекта, затем вернуться в ИСУ, ввести точное название и нажать «Проверить и удалить из ИСУ».
- ИСУ проверяет отсутствие проекта отдельным запросом непосредственно перед удалением. Завершённый, но существующий проект удаление не пройдёт. Ошибки сети, доступа и сервера блокируют удаление в ИСУ.
- После проверки папка перемещается в корзину ИСУ. Проект скрывается из рабочих списков, журнал обновляется. При локальном сбое выполняется возврат папки.
- В Planfix нет официального REST/XML метода удаления проекта: удаление там выполняется пользователем через интерфейс. Автоматически переводить проект в «Завершён» больше не будем.
- Явное «не указано» для структуры сохраняется в текущих и архивных проектах. Старое значение Planfix больше не заменяет его при импорте. При выборе другой структуры защита очистки снимается.
- Очищенное поле отправляется в Planfix явно. Даже если внешний сервис отвергнет очистку, значение в ИСУ останется пустым; ошибка синхронизации будет в журнале контейнера.
- Структуру можно удалить, когда она отвязана от всех неудалённых проектов, включая архив. Если она осталась только в корзине, ссылки очищаются в транзакции, старое название сохраняется в истории этих проектов.
- Ошибки удаления структуры обрабатываются; названия с символом «%» не ломают запрос.
- Escape и кнопка «Закрыть» закрывают окно удаления, пока операция не выполняется. При отказе Planfix окно остаётся открытым для повторной проверки.

Токен ИСУ должен иметь право читать связанные проекты Planfix. Сам проект в интерфейсе Planfix удаляет автор или администратор аккаунта. Восстановление папки из корзины ИСУ не восстанавливает проект Planfix автоматически: его восстановление выполняется отдельно в Planfix.

## Установка на действующем сервере

Загрузите файлы из архива в GitHub с сохранением путей. Команды ниже выполняются на действующем Ubuntu-сервере в папке проекта, где находятся docker-compose.yml и каталог db. Домашний сервер сейчас не используем.

Каждую команду вводите целиком одной строкой. Если команда завершилась ошибкой, следующую не выполняйте.

1. Получить файлы:

```sh
git pull --ff-only
```

2. Сделать резервную копию базы:

```sh
mkdir -p "$HOME/backups/imcstroy"
DB_BACKUP="$HOME/backups/imcstroy/db-before-project-delete-$(date +%F-%H%M%S).sql"
docker compose exec -T db sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB"' > "$DB_BACKUP"
test -s "$DB_BACKUP" && ls -lh "$DB_BACKUP"
```

3. Применить миграцию ДО запуска новой версии:

```sh
docker compose exec -T db sh -c 'psql -v ON_ERROR_STOP=1 -1 -U "$POSTGRES_USER" -d "$POSTGRES_DB"' < db/048_case_organization_clear.sql
```

4. Пересобрать только ИСУ:

```sh
docker compose up -d --no-deps --build filemanager
docker compose ps filemanager
docker compose logs --tail=60 filemanager
```

5. Обновить страницу ИСУ через Ctrl+F5.

## Проверка после установки

1. В архивном журнале выберите «не указано» в структуре проекта, обновите страницу, запустите сверку с Planfix и проверьте, что значение осталось пустым.
2. Если вы уже очищали поле до обновления, но оно вернулось, выберите «не указано» заново: новая отметка явной очистки сохраняется только после установки.
3. Повторите для текущего проекта; проверьте то же значение в карточке проекта.
4. В настройках удалите структуру, которую отвязали от всех текущих и архивных проектов. Используемая структура должна показать понятный отказ.
5. Для удаления возьмите ненужный тестовый проект. Откройте окно удаления в ИСУ и сначала попробуйте проверить без удаления в Planfix: ИСУ должна отказать и оставить папку.
6. Удалите тестовый проект в Planfix, затем повторите проверку в ИСУ. Папка должна появиться в корзине, проект — исчезнуть из рабочих списков.

## Локальные проверки

Пройдено 30 групп сценариев: формирование запросов Planfix, существующий/отсутствующий проект, 401/403/500/502, некорректные ответы, точное подтверждение имени, отказ/успех удаления, возврат папки при сбое, очистка структуры, повторный импорт, защита от конкурентной очистки, транзакция справочника и конфликт внешнего ключа. Окно удаления проверено в настоящем Chrome, включая Escape и ограничения обычного сотрудника.

База и Planfix в тестах заменены управляемыми заглушками. Миграция не выполнялась на настоящем PostgreSQL и живой аккаунт Planfix не изменялся; окончательную интеграционную проверку выполняем после установки.
